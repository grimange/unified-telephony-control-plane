# GN-G2 PHP claim and fingerprint proof

Test-only proposed PHP interoperability seam for the isolated conditional-effect
adapter. No production PHP file, route, table, service binding, Kubernetes writer,
or deployed credential is changed. The current application does **not** already
provide the proposed full-action claim verification endpoint.

## Reproduce

From the repository root:

```bash
tests/gn-g2-effects/verify-php
```

The runner uses the existing PHP 8.4.15 / PHPUnit 11.5.56 image by immutable local
image ID `sha256:9efe210fb8c8e7c90d80fce2b6916b46824f0f0428d6037dd599ec5ef1dd4d7d`.
It mounts production source and these tests read-only, disables external
networking, uses disposable in-memory SQLite, and writes only the sanitized
`/tmp/utcp-gn-g2-output/php-proof.json` artifact. It installs no host packages.
Override the disposable output directory with `UTCP_GN_G2_OUTPUT` if needed.

Run the GN-G2 Go verification between two invocations. The first PHP invocation
exports actual authorization decisions and fingerprint vectors. Its reverse-Go
comparison explicitly skips while `go-proof.json` is absent. The final invocation
requires the Go export and compares every independent PHP fingerprint with Go's
actual result; the full verifier must not count that bootstrap skip as final proof.

## Proof responsibilities

- `ClaimVerificationBridge.php` reads actual operation rows created and leased
  using the production `RuntimeOperationRepository`. It verifies current token,
  attempt, lease expiry, exact expiry binding, leased/running status, tenant and
  RuntimeNode. Verification itself performs no operation transition.
- The test-owned canonical intent record supplies the **future** complete target,
  UID/RV/incarnation, generation, hash, action, replicas, idempotency, audit and
  lifecycle binding. This is deliberately separate from existing operation row
  capabilities. It neither claims those future fields already exist in the
  production schema nor exposes a production authorization route.
- Real repository reclaim and fenced `markRunning` tests reject old/expired
  workers. SQLite proves PHP lifecycle behavior; it does not prove PostgreSQL
  row-lock concurrency, distributed claim/Kubernetes atomicity, or lease renewal.
- `ActionFingerprint` implements the immutable GN-G0 ordered UTF-8 **byte-length**
  encoding independently from Go. Eight positive vectors cover the normative
  hash, both actions, generations above JavaScript precision and at signed-bigint
  maximum, replicas bounds, Unicode opaque identity, opaque RV and retry context.
  Twelve negative vectors reject malformed/coerced/overflow/missing fields.
  All v1 fields are required; no optional defaults are invented. Object member
  ordering does not affect canonical matching; opaque values are never coerced.
- This seam accepts decoded arrays, not wire JSON. Duplicate-key and UTF-8 wire
  rejection belong to the Go mTLS HTTP transport and its permanent regressions.
- `ResultCompatibilityBridge` tests all normative PHP exception mappings while
  retaining the full normalized dispatch/effect/retry/outcome. In particular,
  `outcome_unknown` remains `observe_first` even though its compatibility reason
  is `unavailable_to_control`. It performs no operation completion or retry.

## Artifact format

`php-proof.json` contains `fingerprints` (`name`, complete `action`, `expected`),
`claims` (`name`, complete `action`, exact two-field `response`) and `error_parity`
(`code`, `php_reason`, `dispatch`, `effect`, `retry`). Operation IDs and lease
nonce tokens are generated by the real repository for disposable test rows; they
are not production credentials. A fixed clock makes expiry assertions repeatable.

The Go exporter writes `go-proof.json` with `fingerprints` (`name`, `action`,
`actual`) and optionally actual executed `results` for reverse compatibility
projection. Both exports remain disposable and outside the repository.
