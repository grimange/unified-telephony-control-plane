## Root Cause

The rendered Kamailio configuration added the T3-S2A application-dialog route
with:

```kamailio
if (has_totag()) {
```

but did not load the Kamailio module that exports that command:

```kamailio
loadmodule "siputils.so"
```

The live rollout therefore created a new Kamailio Pod whose process exited with
`exitCode 255` after Kamailio reported that it could not resolve
`has_totag()`. The old pre-T3-S2A Pod stayed Ready only because rolling-update
protection left it running with the previous configuration.

## Official Kamailio Contract

- `has_totag()` is provided by `siputils.so`.
- `kamailio -c -f <config>` is the repository-relevant parser authority for
  syntax, module loading, module parameters, command resolution, and route
  validity.
- `siputils.so` is already present in the pinned image
  `ghcr.io/kamailio/kamailio:5.8.6-bookworm`; no image change is required.

## Correction

The canonical ConfigMap now loads the missing module beside the existing
route-module declarations:

```kamailio
loadmodule "rr.so"
loadmodule "siputils.so"
```

No route logic changed. `has_totag()`, `record_route()`, `loose_route()`, and
`t_relay()` remain in the intended application-dialog route.

## Rendered-Config Parser Guard

`scripts/kamailio-signaling/config-check` now renders the deployable Kamailio

runs the exact pinned image:

```text

  -v <temp cfg>:/tmp/kamailio.cfg:ro \
```

The check covers:

- `infrastructure/kubernetes/base/platform`

- `infrastructure/kubernetes/overlays/local`

Temporary files are created under a temporary directory and removed by the
script trap. No repository file is generated by parser validation.

## ConfigMap Rollout Coupling

The Kamailio Deployment Pod template now carries a deterministic content
checksum:


The checksum is computed from the final rendered `kamailio.cfg` bytes. A
Kamailio configuration-content change therefore changes the Deployment Pod
template and produces a normal Kubernetes rollout when the canonical manifests
are applied. The check rejects a stale checksum and rejects mutable rollout
restart timestamps such as `kubectl.kubernetes.io/restartedAt`.

No reloader controller, sidecar, manual reload command, environment switch, or
timestamp annotation was added.
