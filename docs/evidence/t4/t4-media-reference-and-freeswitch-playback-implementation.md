## Repository contract

UTCP owns the generic opaque `utcp:media/<identifier>` syntax, canonical media
identity, playback control, and the provider-adapter resolution boundary. The
caller/application owns the logical identifier and the application/operator owns
the media content. UTCP does not own a tenant media catalog, upload flow, storage
service, synchronization product, or media administration surface.

Provider adapters resolve only syntactically valid canonical references at the
runtime boundary. Asterisk maps `utcp:media/<id>` to its sanctioned `sound:<id>`
namespace. FreeSWITCH maps it to the managed sound root
`/usr/share/freeswitch/sounds/<id>.wav`. Provider-local values are converted back
to the generic canonical reference for observations; they never become canonical
media identity. No API-container filesystem preflight is used for arbitrary
operator-provisioned media. `media_ref_unresolved` is reserved for a genuine
adapter-boundary transformation failure, while malformed canonical syntax uses
the canonical invalid-reference validation path.

The repository validation asset is `utcp:media/reference-tone`, projected into
the managed Asterisk and FreeSWITCH sound namespaces. It is validation-only and
is not an identifier allowlist. The playback implementation loads `mod_sndfile`,
subscribes to `PLAYBACK_START`/`PLAYBACK_STOP`, preserves
`call.leg.media_started`/`call.leg.media_stopped`, and activates only FreeSWITCH
`media.playback` in the existing capability catalog. Recording, transfer,
event-stream, runtime-observation, and conference capabilities remain dark.

The Asterisk config check now points at the canonical checked-in SIP fixture
component rather than the stale nonexistent local overlay path.

No live Kubernetes, browser, or provider proof was performed for this record.

## Runtime diagnostics and deterministic validation fixture packet

The latest natural live proof established that the canonical
`call.leg.play_media` operation reaches the FreeSWITCH adapter and receives
`+OK`, while the established session remains in `park` and produces no
playback observations. This packet addresses the diagnostic visibility gap and
the proof-asset weakness; it does not claim that the FreeSWITCH playback
execution defect is fixed.

The managed FreeSWITCH image now loads repository-owned `mod_console` with
`autoload_configs/console.conf.xml`. The entrypoint keeps FreeSWITCH in
foreground console mode as PID 1. The pinned FreeSWITCH build requires its
custom `-conf`, `-log`, and `-db` arguments together; `-log` therefore points
only at the existing ephemeral `/var/run/freeswitch` runtime directory, while
console colorization is disabled and the console loglevel is DEBUG. The
operational diagnostic path is `kubectl logs <pod>` through `mod_console` and
container stdout/stderr. No `mod_logfile`, persistent log volume, hostPath,
public endpoint, manual post-start setup, or second durable logging authority
is introduced.

The checked-in `reference-tone.wav.base64` asset remains identified by the
canonical `utcp:media/reference-tone` reference and the existing provider-local
path. It is generated by `scripts/media/generate-reference-tone.py` as a
deterministic 5.000-second, mono, 16-bit PCM, 8000 Hz, 440 Hz tone. The
decoded WAV SHA-256 is
`a2782505c392c5a763e6a8d3ebfdfd904272d5f79c8bc158a04b3273e9ac0d0e`.
`scripts/media/reference-tone-check` rejects invalid encoding, near-zero
duration, silence, and clipping; the FreeSWITCH config checks invoke it.

The image is still built through the existing digest-pinned FreeSWITCH image
lifecycle. The provider-local playback mapping is now:

```text
call.leg.play_media
  -> resolve media_ref
  -> uuid_displace <channel> start <path> 0 mux
  -> uuid_buglist <channel> confirms the displacement media bug

call.leg.stop_media
  -> resolve the canonical active media_ref internally
  -> uuid_displace <channel> stop <path>
  -> uuid_buglist <channel> confirms the displacement media bug is absent
```

The public operation, `media_ref`, capability gate, RuntimeOperation authority,
channel fencing, and normalized observation names are unchanged. A synthetic
adapter test proves that `+OK` without the runtime media bug is a failure. The
canonical live spike could not be run in this packet because the available
canonical FreeSWITCH pods had no established CallLeg/channel; no live success
is claimed.

Focused `MediaReference`, `FreeSwitchEslAdapter`, and
`FreeSwitchEventObservation` tests validate the provider-local mapping,
invalid-reference rejection, fencing, idempotency, and runtime-bug
observation seam. FreeSWITCH config mutation and configuration checks validate
the foreground console path, module/configuration presence, read-only
filesystem boundary, and fixture. Recording interaction, media management,
and all later roadmap work remain explicit non-goals. The next required action
is a narrow Claude Code natural live reproof of start, runtime media evidence,
stop, and normalized observations.
